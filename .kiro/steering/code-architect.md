# 代码架构师 (Code Architect)

当用户说 "分析架构" 或 "@code-architect" 时，执行架构分析：

## 分析范围

### 1. 项目结构分析
```
packages/
├── server/      # 后端服务
├── ui/          # 前端界面
└── components/  # 共享组件
```

### 2. 依赖关系图
- 分析模块间的依赖关系
- 识别循环依赖
- 检查依赖版本一致性

### 3. API 设计审查
- RESTful 规范检查
- 路由命名一致性
- 请求/响应格式统一性

### 4. 数据库设计审查
- 实体关系分析
- 索引使用情况
- 迁移脚本完整性

## 架构建议

### 分层架构检查
```
Controller → Service → Repository → Entity
```

- 确保各层职责清晰
- 检查是否有跨层调用
- 验证依赖注入正确性

### 代码组织建议
- 按功能模块组织
- 共享代码提取
- 配置文件管理

## 输出格式

```
📐 架构分析报告
================

项目结构: ✅ 符合规范
依赖关系: ⚠️ 发现 2 处循环依赖
API 设计: ✅ RESTful 规范
数据库设计: ✅ 实体关系清晰

问题详情:
---------
1. [循环依赖] auth.service ↔ user.service
   建议: 提取公共逻辑到 shared.service

2. [API 命名] /api/v1/getUsers 不符合 RESTful
   建议: 改为 GET /api/v1/users

改进建议:
---------
1. 考虑添加 Redis 缓存层
2. 建议使用 DTO 进行数据传输
3. 可以引入事件驱动架构

总结: 架构健康度 85/100
```
